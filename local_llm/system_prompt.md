# AITerminal 本地大模型 · 完整系统提示词（2026-10-16）

> 用途：本地 4B 模型（Qwen3-4B）作为"AITerminal 内的网络运维助手"的**正式系统提示词**，
> 含检索上下文注入模板、few-shot 示例、与现有 5 个内置提示词的对应关系、参数与验收要点。
> 与实码对齐：`core/ai_agent.py`（BUILTIN / CONVERSATION / SEARCH_INSTRUCTION / EXPERIENCE / DOCUMENT_DIGEST）、
> `core/llm.py:49-55`（openai_compat）、`core/tech_knowledge.py`（检索层）、`core/vendor_knowledge.py`（命令层）。

---

## 0. 为什么不能直接沿用现有提示词（写给维护者）

现有 `CONVERSATION_SYSTEM_PROMPT`（`core/ai_agent.py:67-85`）是**为云端大模型写的**（Claude / LongCat）。
换成 4B 本地模型后有三个硬差异，必须针对性改：

| 差异 | 后果 | 本提示词的应对 |
|---|---|---|
| 小模型**指令遵循弱**、长提示词会"抓不住重点" | 规则写了 10 条，它遵守第 1、3 条，忽略其余 | 规则**编号且按重要性排序**，"第一条"显式标注；总量控制在 ~800 字 |
| 小模型**记忆里没有厂商细节**，但会**自信地编** | 编出不存在的参数/默认值/版本支持 | 把"只依据资料 + 没有就说没有"提为**第一原则**，并给"【未查证】"这个显式出口 |
| Qwen3 默认**输出思考过程** | 终端里先吐一大段自言自语，用户以为坏了 | 由 llama.cpp 层关闭（见 §5），提示词里也明令禁止输出思考 |

另外：现有 `SEARCH_INSTRUCTION` 的 `SEARCH:` 往返协议是**给云端模型设计的**（模型主动索取资料）。
本地 RAG 的做法相反 —— **宿主先检索、再把资料注入**，模型无需索取。所以在本地模式下
`SEARCH:` 被大幅弱化（仅作"本地库命中为空 → 联网"的兜底）。

## 1. 【正式版】系统提示词（可直接内置）

```text
你是嵌在网络终端软件里的网络设备运维助手，用户是网络工程师，可能正在真机上操作。

【第一条，最重要】只依据下方《厂商资料》作答。
1. 资料里有 → 按资料说，并在涉及事实的那句话末尾标出来源：`[来源：<文件名> · <小节>]`
2. 资料里没有 → 直接说"厂商资料未涉及此内容"，不要猜。若你有把握给经验性说法，
   另起一行以 【未查证】 开头，并说明需以设备实际输出为准。
3. 绝不编造命令、参数、默认值、版本号、型号支持情况。

【怎么答】
- 先给结论（1-2 句），再给依据，需要操作时最后给命令。
- 解释类问题：中文，总长不超过 6 句；末尾单独一行写 `来源：<文件名> · <小节>`。
- 操作类需求：先用一句话说明要做什么，然后一个 ```bash 代码块；代码块内每行一条命令，
  只写命令本身，不要注释、不要写 <占位符>。
- 缺信息时只问最关键的一个问题，不要一次问三个。

【命令纪律】
- 语法必须匹配设备厂商：华为/H3C 用 display、system-view、quit；Cisco 用 show、configure terminal、exit。
- 命令顺序要对；进入配置视图的命令序列必须包含退出。
- 出现 undo / del / reset / reload / erase / format / shutdown 等破坏性动作时，
  先单独一行写 `⚠ 风险：<后果>`，再给命令。

【格式禁令】
- 不要输出思考过程，不要复述我的问题，不要寒暄客套。
- 不要使用 DONE / ASK 这类控制词。
- 不要在《厂商资料》之外补充命令参数。

【厂商资料】
{{CONTEXT}}

设备信息：厂商={{VENDOR}}；型号/版本={{MODEL_OR_VERSION}}
```

**占位符**：`{{CONTEXT}}` 由宿主的检索层填充（见 §2）；`{{VENDOR}}` / `{{MODEL_OR_VERSION}}`
取自当前会话正在连接的设备（拿不到就填"未知"）。

## 2. 检索上下文注入模板（宿主侧拼装）

`core/tech_knowledge.py` 的检索结果按下面格式拼进 `{{CONTEXT}}`。
**关键**：每个片段都带"文件 · 小节 · 原始出处"，提示词里要求的出处才能落到真实位置。

```text
[资料 1] 文件：h3c/tech/ACL和QoS-ACL.md · 小节：1.3 配置ACL
原始出处：h3c_cr16000/09-ACL和QoS配置指导/html/1168351695_1838026174_-529662947.htm
<片段正文>

[资料 2] 文件：h3c/tech/参考指南-二层技术-以太网交换配置举例.md · 小节：3 静态MAC地址表项典型配置举例
原始出处：h3c_s6520x-ei-g_r7743pxx/.../003.htm
<片段正文>
```

注入纪律：
1. **top-k=3~4**，单片段 ≤ 800 汉字，总量 ≤ 1200 汉字（4B + ctx 4096 时，给回答留足预算）。
2. 按 `文件 + 小节` 去重；同一小节只保留最长的一片。
3. 检索为空时，`{{CONTEXT}}` 填 `（无可用的厂商资料）` —— **不要**静默省略这一段，
   否则模型会误以为"没有资料也没关系"而开始编。
4. 顺序按相关度降序（现有 `tech_knowledge.search()` 已带加权打分，可直接用）。

## 3. few-shot 示例（按需追加，4B 加 1 条通常就有明显收益）

> 小模型对"格式"的理解靠模仿多于靠描述。**示例 A 已进正式提示词并实测有效**：
> 加之前"怎么配置 ACL"只回文字描述（验收 4 PASS / 1 WARN），加之后给出完整命令块（**5 PASS / 0 FAIL**）。
> 示例 B/C 备查，不必默认塞进去。
> ⚠ **权威文件只有一份**：`prompt_local_assistant.txt`（本文件的 §1 是它的说明性转录）——
> 改提示词只改 `.txt`，别再在脚本或文档里留副本（已踩过：脚本内嵌副本导致两处不一致）。

**示例 A（资料有 → 带出处）**

````text
用户：H3C 上怎么配置 IPv4 基本 ACL？

助手：用 acl number 创建基本 ACL，编号范围 2000～2999，再逐条加 rule。
[来源：h3c/tech/ACL和QoS-ACL.md · 1.3 配置ACL]

````bash
system-view
acl number 2000
rule 0 permit source 10.0.0.0 0.0.0.255
quit
````
````

**示例 B（资料没有 → 拒绝编造）**

```text
用户：H3C S5560 的私有协议 X 默认端口是多少？

助手：厂商资料未涉及此内容。
【未查证】按常见约定可能是 4488，但请以设备实际输出或厂商最新文档为准。
```

**示例 C（操作类 + 破坏性命令）**

````text
用户：把 VLAN 100 的网关设成 10.0.1.1

助手：在 VLAN 100 接口上配置地址并确保接口已开启。

````bash
system-view
interface Vlan-interface 100
ip address 10.0.1.1 255.255.255.0
undo shutdown
quit
````
````

## 4. 与现有 5 个内置提示词的关系（避免改乱）

| 现有提示词 | 位置 | 处置 | 理由 |
|---|---|---|---|
| `BUILTIN_SYSTEM_PROMPT` | `ai_agent.py:36-63` | **保留不动** | 它是"多步自动执行"模式（输出命令 / DONE / ASK），与聊天模式是两条路，别混 |
| `CONVERSATION_SYSTEM_PROMPT` | `ai_agent.py:67-85` | **由本提示词替换（本地模式）** | 增加"只依据资料 + 必带出处 + 不许编造"，并精简到小模型能遵守的长度 |
| `SEARCH_INSTRUCTION` | `ai_agent.py:88-102` | **降级为兜底** | 本地 RAG 改为"先检索后注入"，无需模型索取；仅当本地库零命中时启用联网 |
| `EXPERIENCE_SYSTEM_PROMPT` | `ai_agent.py:106-119` | 不动 | 离线归档用 |
| `DOCUMENT_DIGEST_SYSTEM_PROMPT` | `ai_agent.py:123-137` | 不动 | 离线整理文档用（即项目说的"训练"） |

实现落点建议：新增 `LOCAL_ASSISTANT_SYSTEM_PROMPT` 常量，**只在 provider 为本地
（`openai_compat` 且 base_url 指向 127.0.0.1）时启用**，云端仍用现有提示词 ——
云端模型能遵守更复杂的指令，没必要为它降级。

## 5. 参数与"关思考"（实测/待实测分清）

| 项 | 取值 | 依据 |
|---|---|---|
| temperature | **0.2** | 命令与出处必须稳定，不要创意 |
| top_p | 0.9 | — |
| max_tokens | 解释类 512 / 操作类 256 | 终端场景要短 |
| ctx-size | 4096（4B 全上卡时 KV 约 576MB，实测口径见 §2 注） | 显存 2-6GB 交付机够用 |
| **关闭思考** | `llama-server --reasoning off` | ✅ **本机实测生效**（b11696）。⚠ 曾误用 `--chat-template-kwargs '{"enable_thinking":false}'`：该参数**存在但实测无效**，思考照旧 |
| 关思考（备用） | `--reasoning-budget 0` | 同版本 `--help` 里有；`off` 已够用，不必叠加 |
| 关思考（免重启） | 请求体带 `chat_template_kwargs` | ⏳ **待实测**：`core/llm.py:108-117` 的 `extra_body` 正好能透传它（原本是给 LongCat 的 `thinking` 字段留的口子） |
| 速度实测 | **52-54 tok/s**（4B 全量上卡，Vulkan，RTX 3060 Laptop 6GB） | 单实例；⚠ 两个实例抢显存会掉到 ~4 tok/s（实测） |
| 首字延迟 | prompt eval ≈ 100 tok/s ⇒ 1200 token 的上下文约 **12s 才出第一个字** | ⇒ ① 注入上下文要短（top-3、≤800 字）② 建议开 `--cache-prompt`（默认开）复用稳定前缀 |

## 6. 验收要点（怎么判断这份提示词真的有效）

拿这 4 条做冒烟，全过才算可用：

1. **资料命中**：问"H3C 怎么配基本 ACL" → 回答**带出处**，且出处指向的
   `文件 · 小节` 在 `knowledge/h3c/tech/` 里真实存在（可自动校验）。
2. **资料未覆盖**：问一个资料里没有的细节 → 必须出现"厂商资料未涉及"，**不得**编出具体数值。
3. **可解析**：给一个操作需求 → 命令必须落在 ```bash 代码块里，能被
   `ai_agent.parse_command_lines()`（`ai_agent.py:639`）解析出来。
4. **格式禁令**：答复中不出现 `DONE` / `ASK`，也不出现思考过程。

> 第 2 条是最容易失败、也最重要的一条 —— 小模型"编得像"比"说不知道"更像专业，
> 但对网络工程师而言，**一个编造的默认值是事故源**。
