# NetOps Terminal 开发文档

> 集成 AI 辅助功能的网络设备终端工具
> 版本: 0.7.0 | 更新: 2026-09

---

## 1. 项目概述

NetOps Terminal 是一款面向网络运维人员的桌面终端工具，支持 SSH / Telnet / Serial(Console) 三种连接方式，
在传统终端之上叠加了一个 AI 智能体层：它可以读取设备输出、判断设备厂商、生成下一步排查或配置命令，
并在"自动模式"下按轮次自动下发命令，直到任务完成。

典型使用场景：

- 新设备上线前批量巡检（版本、接口、CPU/内存、日志）
- 故障排查（接口不通、环路、ARP/MAC 异常）
- 配置下发与备份（命令模板 + 批量下发 + 配置快照比对）
- 通过 Console 口救砖设备（设备无法通过管理网访问时）

v0.2 在终端与 AI 之上补齐了日常运维闭环：**模板化批量下发 → 配置快照采集 →
前后差异比对 → 会话日志留痕 → 会话一键恢复**。

v0.3 进一步对齐了两类真实诉求：

- **AI 能自己上网查**：内置联网检索（百度 / 必应 / DuckDuckGo / SearXNG），
  AI 遇到不确定的命令语法或报错含义时输出 `SEARCH: 关键词`，系统检索后把资料回填再生成命令；
  也可以在"联网查询"页签直接提问，回答带参考来源可点击。
- **Console 兼容性对齐 MobaXterm**：完整串口帧格式、流控、DTR/RTS 电平、Break 信号、
  运行时切波特率、字符发送间隔、自动重连、本地回显、端口枚举带描述。

v0.4 补上"用自己下载的资料查命令"：

- **本地资料库**：点一个按钮把下载好的命令手册 / 配置案例 / 培训文档导入统一目录，
  自动抽取正文建索引；AI 查命令时**先查本地资料库，再联网**。
  支持 PDF / Word / Excel / PPT / txt / md / html / csv / 日志 / 配置 / zip，
  其中 docx、xlsx、pptx 用标准库直接解析，不需要额外的 Office 库。

v0.5 让资料库**越用越厚**：

- **一键沉淀**：AI 查到的命令、生成的命令清单，点「💾 存为资料」就存回本地资料库，
  自动带上时间、设备、厂商、任务与标签；下次问同一主题直接命中自己的积累，
  形成个人命令知识库。

v0.6 补齐批量运维的三块短板：

- **批量下发改为按提示符判断**：不再靠固定间隔猜，而是等设备输出末尾回到提示符
  （`> ] # $ %`）且静默 0.3 秒再发下一条；遇到 `---- More ----` 自动翻页，
  遇到 `[Y/N]` 确认提示停下来交人工处理。
- **多设备并发巡检**：同时对多台设备跑同一组命令（线程池控并发），
  结果导出 Excel（巡检信息 / 巡检汇总 / 命令明细 三个工作表）。
- **笔记管理增强**：按分类、标签、关键词筛选笔记，勾选后批量导出成一份手册
  （Markdown 或可直接打印的 HTML）。

v0.7 补齐安全与模型两块：

- **配置命令确认闸门**：配置类命令下发前必须先展示命令清单并人工确认；
  AI 自动模式下生成的配置命令只入待执行队列、不自动下发。
- **多模型提供方**：除 Anthropic Claude 外，支持 **DeepSeek** 与任意
  **OpenAI 兼容接口**（vLLM / Ollama / 中转站），各提供方的密钥、模型、接口地址分开保存。

## 2. 技术架构

```
┌─────────────────────────────────────────────┐
│                  UI 层                       │
│  主窗口 │ 终端控件 │ AI面板 │ 连接管理 │ 标签页  │
├─────────────────────────────────────────────┤
│                 核心层                        │
│  SSH连接器 │ Telnet连接器 │ 串口连接器       │
├─────────────────────────────────────────────┤
│                 AI 层                         │
│  输出分析 │ 命令生成 │ 任务规划 │ 上下文管理  │
├─────────────────────────────────────────────┤
│                检索层                         │
│  本地资料库 │ 百度/必应/DuckDuckGo/SearXNG   │
│  正文抽取(PDF/Office/HTML) │ 关键词检索打分    │
├─────────────────────────────────────────────┤
│                 依赖层                        │
│  Paramiko │ pyserial │ Anthropic SDK │ PyQt6 │
└─────────────────────────────────────────────┘
```

数据流：

```
设备 ──socket──> 连接器读线程 ──┬──> connector._buffer ──100ms轮询──> 终端控件显示
                               └──> output_received 信号 ──> 会话输出记录（供 AI 使用）
                                        │
                                        ▼
                              AIAgent.analyze() ──> 命令 ──> connector.send()
                                        │
                                        ├─ SEARCH: 关键词 ─┬─> 本地资料库检索（优先）
                                        │                  └─> 联网检索
                                        │        └─> 资料回填 ──> 再分析
                                        └─ 命令 ──> 待执行队列 / 自动模式下发

资料导入流:
  用户下载的手册 ──[导入资料按钮]──> ~/.aiterminal/knowledge/
                                    └─> 抽取正文 ──> 分块建索引(.index.json)

知识沉淀流（越用越厚）:
  AI 回答 / 命令清单 ──[💾 存为资料]──> knowledge/<分类>/<标题>.md
                                        └─> 增量建索引 ──> 下次检索直接命中

批量运维流:
  一批命令 ──[等提示符]──> 单台设备（批量下发）
  一批设备 ──[线程池并发]──> PatrolRunner ──> 结果 ──> Excel（3 个工作表）
```

设计要点：

- **读写分离**：每个连接器都有独立后台读线程，UI 线程只做搬运，不阻塞界面。
- **单一显示路径**：终端内容只由 100ms 定时器从 `connector.get_output()` 取出后渲染，
  避免"信号 + 轮询"双通道导致的重复输出。
- **AI 上下文与显示解耦**：会话单独维护最近 20000 字符的输出记录，
  AI 消费它时清空，因此不会和 UI 的缓冲区读取互相抢数据。
- **AI 计算在线程外**：所有 API 调用都在后台线程执行，通过 Qt 信号回到主线程更新界面。

## 4. 模块说明

### 4.1 core/connector.py — 连接基类

所有连接器继承 `BaseConnector(QObject)`，统一接口：

| 成员 | 说明 |
| --- | --- |
| `output_received(str)` | 收到设备输出的信号 |
| `connection_lost()` | 连接断开信号 |
| `error_occurred(str)` | 错误信号 |
| `connect(**kwargs) -> bool` | 建立连接 |
| `send(command)` | 发送命令（自动补换行） |
| `send_raw(data)` | 发送原始数据（Ctrl+C、Tab 等） |
| `disconnect()` | 断开连接 |
| `is_connected() -> bool` | 连接状态 |
| `get_output() -> str` | 取出并清空缓冲区 |
| `get_output_block(timeout) -> str` | 阻塞读取直到超时无新数据 |
| `info() -> str` | 一句话描述（状态栏用） |

### 4.2 core/ssh_connector.py

基于 Paramiko，`invoke_shell(term='vt100', 200x50)` 建立交互式通道。
支持密码与密钥认证，认证失败/网络异常分别给出可读提示。

### 4.3 core/telnet_connector.py

> **重要**：Python 3.13 已从标准库移除 `telnetlib`。

本模块在导入时探测 `telnetlib`：可用则直接使用；不可用则回退到内置的
`_MiniTelnet`（纯 socket 实现，处理 IAC 选项协商、SB 子协商、`read_until` /
`read_very_eager` / `write` / `close`），对外行为保持一致，因此同一份上层代码
在 Python 3.9 ~ 3.13 都能运行。

### 4.4 core/serial_connector.py — Console 串口

对标 MobaXterm 的 Console 兼容能力，参数与功能：

| 能力 | 说明 |
| --- | --- |
| 帧格式 | 数据位 5~8、校验 N/E/O/M/S、停止位 1/1.5/2、波特率 1200~921600 可自定义 |
| 流控 | 无 / RTS-CTS 硬件 / XON-XOFF 软件 / DSR-DTR |
| 控制线 | 打开时与运行时可设置 DTR、RTS 电平 |
| Break | `send_break(duration)`，用于打断设备启动进 BootROM（驱动不支持时回退为手动拉低 TX） |
| 运行时改波特率 | `set_baudrate()`，设备启动过程中 console 速率变化时无需重连 |
| 行结束符 | 默认 `\r`（多数网络设备只认 CR），可切 `\n` / `\r\n` / 不追加 |
| 字符间隔 | `char_delay_ms` 逐字符发送，兼容老设备与长线缆 |
| 自动重连 | 读线程捕获端口异常后按间隔重开，发出 `reconnecting/reconnected` 信号 |
| 本地回显 | 由终端控件负责（设备不回显时使用） |
| 端口枚举 | `list_ports_detailed()` 返回端口号 + 设备描述，便于辨认 |
| 错误翻译 | 端口被占用 / 不存在等常见报错翻译成可操作的中文提示 |

打开串口时会清一次输入输出缓冲，避免把上次残留数据当成本次设备输出。

### 4.4.1 core/ssh_connector.py 与 core/telnet_connector.py

- SSH：Paramiko 交互式 shell，开启 transport keepalive（30s），支持密码/密钥认证，
  认证失败与网络异常分别给出可读提示。
- Telnet：Python 3.13 起标准库移除了 `telnetlib`，因此内置了纯 socket 的 `_MiniTelnet`
  作为回退（含 IAC 选项协商），并支持发送 Telnet BREAK。

### 4.5 core/terminal.py — 终端模拟器

不依赖 Qt，可单独单元测试：

- `TerminalBuffer.strip_ansi()`：剥离 CSI/OSC/单字符转义
- `TerminalBuffer.feed(data)`：处理 `\r\n`、`\r` 行内覆盖、`\b` 退格、`\x07` 响铃，
  返回可直接追加显示的文本，并维护带行数上限的屏幕缓冲
- `detect_vendor(output)`：从输出中识别 华为 / H3C / Cisco / 锐捷
- `clean_prompt_tail(text)`：去掉尾部提示符，便于交给 AI

### 4.6 core/ai_agent.py — AI 智能体

- 系统提示词约束模型**只输出命令**，用 `DONE` 表示任务完成、`ASK` 表示需要人工确认
- 上下文保留最近 20 条消息（约 10 轮）
- `analyze()`：分析输出 → 生成下一步命令
- `analyze_config()`：针对配置文本给修改建议
- `explain()`：用自然语言解释输出
- `filter_commands()`：把回复拆成命令列表，并过滤危险命令
- `is_dangerous()`：正则黑名单（reboot / delete / erase / undo all / factory-reset …）
- **联网检索**（v0.3）：
  - 注入 `WebSearchClient` 后，系统提示词会自动追加检索协议
  - `parse_search_request()`：解析 AI 输出的 `SEARCH: 关键词`
  - `web_context()`：执行检索并返回可回填的资料文本（失败时明确告知"查不到"，避免编造）
  - `research()`：检索 → 阅读正文 → 基于资料作答，回答带 `[序号]` 引用，并发 `research_ready` 信号

### 4.7 core/session.py — 会话管理

- `SessionInfo`：会话元数据 + 最近输出记录（`record_output` / `consume_output`）
- `SessionManager`：创建/关闭/切换会话，命令下发，AI 生命周期管理
- `ai_step()`：执行一轮 AI 分析，返回 `(命令列表, 被拦截命令, 状态)`
  状态取值 `ok / done / skip / stopped`，主窗口据此决定是否暂停自动模式

### 4.8 ui/main_window.py — 主窗口

- 标签页承载多个会话，AI 面板以 QDockWidget 停靠在右侧
- 工具栏：新建连接 / AI开关 / AI分析一次 / 断开 / 清屏 / 保存日志
- 菜单：文件、会话、AI、帮助
- 定时器：100ms 刷新终端显示；1000ms 驱动 AI 自动模式
- 自动模式触发条件：AI 已启用 → 连接正常 → 有新输出 → 距最后一次输出 ≥ 0.8s（输出已稳定）

### 4.9 ui/terminal_widget.py — 终端控件

- 按键拦截：Enter 发送、Backspace/↑↓ 编辑命令缓冲与历史、Ctrl+C 中断、Ctrl+L 清屏、Tab 补全
- 关键修正：**Backspace/方向键不会再去修改已显示的设备输出**（原实现会误删历史输出）
- 底部输入回显条实时显示当前输入，避免"看不到自己打了什么"
- 输出经 `TerminalBuffer` 清洗后渲染，`\r` 进度条不会刷屏

### 4.10 ui/session_tab.py — 会话标签页

顶部信息条（会话名 / 协议目标 / 连接状态灯 / AI 标记）+ 终端主体，
提供"批量命令"（多行逐条下发）、"Ctrl+C"、"清屏"、"保存日志"按钮。

### 4.11 ui/connect_dialog.py — 连接对话框

快速预设、协议切换（Serial 时自动隐藏主机参数、显示串口参数）、密钥文件选择、
串口号枚举刷新、记住上次连接（默认不保存密码）。

### 4.12 ui/ai_panel.py — AI 面板

分为三个页签：

| 页签 | 内容 |
| --- | --- |
| **AI 助手** | API Key / 模型、任务描述与模板、厂商快捷命令、**屏幕内容预览（AI 可见）**、AI 输出日志、分析/执行/解释/清空、自动模式开关 |
| **联网查询** | 检索后端与条数设置、提问输入、AI 回答、参考来源列表（双击用浏览器打开）、"允许 AI 自主联网检索"开关 |
| **待执行** | AI 生成的命令进入队列，可编辑、勾选、执行勾选项/执行全部、移除、清空 |

"屏幕内容"预览区实时显示当前会话最近捕获的设备输出，也就是 AI 实际能看到的内容，
便于判断"AI 是否看全了"。

### 4.12.1 ui/serial_dialog.py — 串口控制

Console 现场调试面板：

- 发送 Break（可设时长），支持**连续 Break** 模式（设备上电时连点进 BootROM）
- DTR / RTS 电平实时切换
- 运行时切换波特率、调整行结束符与字符发送间隔
- 手动"重新连接"
- 实时显示连接状态与当前端口/帧格式
- 内置 Console 常见问题提示

### 4.13 config/settings.py — 全局配置

配置优先级：环境变量 > `~/.aiterminal/settings.json` > 默认值。
支持 `.env`（`ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL`）、最近连接记录、窗口尺寸记忆。

### 4.14 config/presets.py — 预设

`PRESET_CONNECTIONS` 快速预设、`PROTOCOL_DEFAULTS` 默认端口、

### 4.17 core/batch.py — 批量下发（v0.6 改为等提示符）

两种等待方式，界面上可切换：

| 方式 | 判断依据 | 适用 |
| --- | --- | --- |
| **等提示符（默认）** | 输出末尾回到提示符（`> ] # $ %`）且静默 `quiet_time`（默认 0.3s） | 慢设备、长输出，最接近人工敲命令 |
| 固定间隔 | 每条命令后按设定毫秒等待 | 设备提示符不标准时的兜底 |

`CommandWaiter` 的完整判定顺序：

1. **分页**：末尾出现 `---- More ----` → 自动补一个空格翻页（先清判定窗口再补空格，
   否则会把翻页返回的内容一起清掉），并记录翻页次数
2. **人工确认**：末尾出现 `[Y/N]` / `(y/n)` / `Are you sure` → 返回 `confirm`，
   停止后续命令交给人工（**不自动应答**，避免误操作）。这一条必须排在提示符判定之前，
   因为 `[Y/N]` 本身也以 `]` 结尾
3. **提示符返回**：末尾是提示符字符且静默够久 → `prompt`
4. **静默兜底**：有输出但长时间没新内容 → `silence`（提示符不标准的设备）
5. **超时 / 断开** → `timeout` / `disconnected`

**关键实现**：等待逻辑通过连接器的**输出监听器**（`add_output_listener`）观察回显，
而不是读缓冲区。因为界面每 100ms 会把缓冲区取走显示，批处理再去读就拿不到数据了；
监听器是在读线程里同步回调的旁路通道，不消耗缓冲区，两者互不干扰。
用监听器而不是 Qt 信号，是因为信号在子线程里是排队投递的，没有事件循环就收不到。

结果保存：每条命令的记录（命令 / 状态 / 耗时 / 输出）会留在 `runner.get_results()`，
可用「工具 → 导出上次批量下发结果」导出 Excel。

### 4.18 core/patrol.py — 多设备并发巡检

- **线程池并发**：`ThreadPoolExecutor`，并发数可调（默认 4，上限 32）
- **独立连接**：巡检自己新建连接，不占用也不影响界面上已打开的会话，跑完即断开
- **复用等待逻辑**：每台设备一个 `CommandWaiter`，按各自回显判断命令是否执行完
- **进度上报**：`device_started` / `device_command` / `device_done` / `log` / `finished`
- **导出**：`export_patrol_excel()` 生成三个工作表

| 工作表 | 内容 |
| --- | --- |
| 巡检信息 | 任务名、起止时间、设备数、成功/异常数、并发数、巡检命令清单 |
| 巡检汇总 | 序号 / 设备 / 协议 / 地址 / 状态 / 耗时 / 命令数 / 正常数 / 异常数 / 说明 |
| 命令明细 | 设备 / 序号 / 命令 / 状态 / 耗时 / 输出 |

### 4.19 core/xlsx_writer.py — 标准库写 Excel

不引入 openpyxl：用 `zipfile` 直接写 OOXML（`[Content_Types].xml`、`workbook.xml`、

### 4.24 core/web_search.py — 联网检索

只依赖标准库 `urllib`，**不需要额外的搜索 API Key**。

| 后端 | 说明 |
| --- | --- |
| `baidu` | 百度，中文技术内容召回最好（默认自动模式的首选） |
| `bing` | 必应，链接为直链，稳定性好 |
| `duckduckgo` | DuckDuckGo HTML 版 |
| `searxng` | 自建/公共 SearXNG 实例（设置里填地址），优先 JSON 接口 |
| `auto` | 按 baidu → bing → duckduckgo → searxng 顺序回退，任一有结果即返回 |
| `off` | 关闭联网检索 |

关键处理：

- **跳转链接解析**：百度/必应返回的是 `/link?url=`、`/ck/a?...` 跳转链接，
  会跟随重定向取回真实地址；必应链接里的 `&amp;` 实体先反转义再解 base64
- **正文抽取**：`html_to_text()` 去掉 script/style/注释，块级标签转换行，供 AI 阅读
- **容错**：抓取失败的站点直接跳过，继续尝试后续结果，直到拿到设定篇数的正文
- **错误可见**：`last_error` / `last_backend` 记录实际使用的后端与失败原因，界面上可看到

### 4.25 联网检索的两种用法

1. **AI 自主检索**（默认开启）：分析设备输出时若拿不准命令语法或报错含义，
   AI 输出 `SEARCH: 关键词`，程序检索并把资料回填，AI 再据此生成命令（每轮最多 2 次）。
   可在 AI 面板关闭该能力。
2. **人工提问**：在"联网查询"页签直接问，如"H3C S5560 怎么配置端口镜像"，
   回答基于检索到的资料并标注引用序号，下方列出参考来源，双击用浏览器打开。
   也可以点"带上屏幕内容查询"，把设备当前输出一起作为背景提交。

### 4.26 命令下发的三种方式

| 方式 | 入口 | 适用 |
| --- | --- | --- |
| 人工确认后执行 | 待执行队列：勾选 → 执行勾选项 | 生产环境，逐条过目 |
| 单条执行 | AI 面板"执行AI命令" | 快速执行 AI 最近生成的一条 |
| 自动执行 | 勾选"自动模式" | 巡检/排查等可放手的场景，危险命令仍会被拦截 |

三种方式最终都走同一条下发路径（`connector.send()`），并复用批量执行器与危险命令拦截。

### 4.27 core/knowledge.py — 本地资料库

**目录**：`~/.aiterminal/knowledge/`（可在界面上更换），索引缓存为同目录下的 `.index.json`。

**导入**（`import_paths`）：

| 输入 | 行为 |
| --- | --- |
| 文件 | 复制（默认）或移动进资料库；同名文件自动加序号，不覆盖已有资料 |
| 文件夹 | 递归导入，并在资料库下建同名子目录，保持分类 |
| zip 压缩包 | 解出内部受支持的文件到同名子目录（含 zip slip 防护） |
| 剪贴板文本 | 直接存成 `.md` 文档 |
| 可选子目录 | 界面上填"H3C"/"华为S5700"等，自动归入对应子目录 |

**正文抽取**（`extract_text`）：

| 格式 | 实现方式 |
| --- | --- |
| txt / md / log / cfg / conf / ini / json / yaml / xml / rst | 直接读取，自动尝试 utf-8 / gb18030 / gbk 编码 |
| csv / tsv | 转成"竖线分隔"文本，便于按列检索 |
| html / htm | 去脚本样式、块级标签转换行 |
| **docx** | `zipfile` 读 `word/document.xml`（含页眉页脚），**不需要 python-docx** |
| **xlsx** | `zipfile` 读 `sharedStrings.xml` + `worksheets`，**不需要 openpyxl** |
| **pptx** | `zipfile` 读 `slides/slideN.xml`，按页输出 |
| **pdf** | `pypdf`（唯一额外依赖），按页输出并标注页码 |
| doc / xls / ppt（老格式） | 明确提示"请另存为新格式或导出 PDF" |

**索引**（`build_index`）：按文件 mtime + size 判断是否需要重建，未变化的直接复用缓存；
长文档按 800 字符左右分块，块之间保留一行重叠，避免命令被切断后丢上下文。

**检索**（`search`）：英文/数字按词、中文按 bigram 分词，用 TF-IDF 风格打分，
文件名命中额外加权（手册名常带型号，用户也常按型号搜），长块做归一化避免霸榜。
返回片段带来源文件名、段号、匹配度和命中词，方便在界面上验证。

### 4.28 资料检索的优先级

```
用户提问 / AI 输出 SEARCH: 关键词
        │
        ├─ 1. 本地资料库（优先，离线、贴合自己设备型号）
        └─ 2. 联网检索（本地没有或不够时补充）
        │
        └─> 合并成【本地资料库】+【联网检索】两段上下文回填给模型
```

回答时要求模型"本地资料优先于联网资料"，并在参考来源列表里用
`【本地】/【网页】` 区分，本地来源双击打开对应文档，网页来源双击打开浏览器。

### 4.31 core/llm.py — 多模型提供方（v0.7）

上层（`AIAgent`）只调用 `LLMClient.chat()`，不关心是哪家模型。

| 提供方 | 接口 | 默认模型 | 依赖 |
| --- | --- | --- | --- |
| `anthropic` | Anthropic 官方 SDK | claude-sonnet-4-20250514 | anthropic 包 |
| `deepseek` | https://api.deepseek.com（OpenAI 兼容） | deepseek-chat | 无（标准库） |
| `openai_compat` | 用户填写的地址（vLLM / Ollama / 中转站） | gpt-4o-mini | 无（标准库） |

实现要点：

- **OpenAI 兼容协议用标准库 urllib 实现**，不引入 openai 包（保持依赖精简）
- 地址拼接兼容三种写法：`https://api.deepseek.com`、`.../v1`、完整 `.../chat/completions`
- 请求体：`system` 作为首条 `system` 消息；带 `max_tokens` / `temperature` / `stream=false`
- **错误翻译成可读中文**：401 密钥无效、402 余额不足、404 模型名或地址不对、
  429 频率限制；网关错误里若包着 `connection refused` 会改说"无法连接到接口地址"
- 推理类模型（deepseek-reasoner）把内容放在 `reasoning_content` 时也能取到

各提供方的密钥、模型、接口地址**分开保存**（`provider_keys` / `provider_configs`），
界面上切换提供方时不会互相覆盖。

### 4.32 core/safety.py — 命令安全分级（v0.7）

**用户强制约定**：配置类命令下发前必须先展示命令清单并等人工确认。

判定采用**白名单**方式：

```
只有明确属于只读查询的命令才算安全：
  display / show / ping / tracert / traceroute / dir / more / type / help /
  screen-length / terminal length / quit / exit / return / end …
其余一律按配置命令处理（包括未知命令 —— 宁可多问一次）
```

拦截点：

| 位置 | 行为 |
| --- | --- |
| `main_window.run_batch()` | 批量下发 / 待执行队列 / 巡检都走这里，含配置命令时先弹确认框 |
| `patrol_dialog.start_patrol()` | 巡检命令含配置命令时先确认 |
| `SessionManager.ai_step()` | AI 自动模式下生成的配置命令**不自动下发**，转待执行队列并暂停自动模式（状态 `queued`） |
| 工具菜单 | "配置命令下发前需确认"开关，**默认勾选** |

确认框（`ui/command_confirm.py`）会列出全部命令、把配置命令标红、给出风险提示
（"设备将进入配置视图" / "会保存配置" / "会删除配置项" / "会导致设备重启"），
并需二次确认；命令原文可一键复制留档。

### Console 连接排查顺序

1. **端口被占用** → 关掉 MobaXterm / SecureCRT / PuTTY 等占用同一串口的软件
2. **完全没有输出** → 按回车；仍无输出就把波特率在 9600 / 115200 之间试一遍
3. **乱码** → 波特率或校验位不对，先确认 8-N-1，再逐个试波特率
4. **丢字符 / 只显示一半** → 把"字符间隔"调到 5~10ms
5. **要进 BootROM** → 设备上电瞬间用"串口控制"连点 Break，或把 DTR 拉低
6. **要看完整启动日志** → 先接好串口再给设备上电

> 关于密码：默认不保存。若在配置文件中把 `save_passwords` 设为 `true`，
> 会话列表里的密码会用 base64 混淆后保存 —— **这只是避免明文直读，不是加密**。

## 6. 已知限制

1. **终端不是完整终端模拟器**：没有实现光标定位（CSI H/f）、全屏 TUI 应用（如 `top`）。
   跨数据包的 `\r` 覆盖（部分设备的进度条）无法撤回已渲染内容，可能显示为多行重复；
   同一数据包内的 `\r`/`\b` 已正确处理。若需要完整兼容，后续可引入 `pyte` 做屏幕仿真。
2. **本地回显依赖设备**：设备关闭 echo 时，终端区不会显示你输入的内容，
   但界面底部输入回显条会实时显示当前输入。
3. **AI 自动模式是串行轮次制**：一轮分析 → 下发命令 → 等输出稳定 → 下一轮，
   不做流式解析，因此每轮之间有约 1 秒以上的间隔。
4. **单进程内的会话是线程级的**：不做跨进程/多窗口共享。
5. **密码保存只是混淆**：`save_passwords=true` 时使用 base64 编码，不是加密，
   任何能读到配置文件的人都能还原；涉及生产环境建议保持默认（不保存）。
6. **批量下发是固定间隔**：不解析设备回显判断上一条是否执行完，
   对慢设备请把间隔调大（界面上可调，默认 500ms）。
7. **联网检索依赖搜索引擎页面结构**：百度/必应改版后解析规则可能失效，
   此时可在设置里切换后端（`search_backend`）或改用自建 SearXNG 实例。
8. **部分站点会拒绝抓取**：正文抽取遇到 403/反爬会跳过该条，只保留标题与摘要，
   不影响继续尝试其他结果。
9. **Console 能力受驱动限制**：`send_break` 与 DTR/RTS 依赖 USB 转串口芯片驱动，
   少数廉价芯片不支持（界面会给出失败提示）。自动重连的前提是设备驱动能感知拔插。
10. **本地资料检索是关键词匹配**，不是语义检索：问法和手册措辞差太远可能查不到。
    建议关键词里带上厂商、型号或完整命令（如 `H3C S5560 端口镜像`）。
11. **扫描件 PDF 无法检索**：图片型 PDF 抽不出文本，需要先做 OCR 再导入
    （导入时会明确提示"未抽取到文本"）。
12. **老版 Office 二进制格式不支持**：`.doc` / `.xls` / `.ppt` 请另存为新格式或导出 PDF；
    `.rar` / `.7z` 请先解压。
13. **单篇文档索引上限 40 万字符**：超长手册会被截断，避免索引膨胀拖慢检索。
14. **沉淀笔记不做自动去重**：同名文件加序号并存，检索时按相似片段去重；
    重复内容需要人工在资料库窗口里清理。
15. **"等提示符"依赖提示符可识别**：判定依据是输出末尾是否为 `> ] # $ %`。
    如果设备提示符很特殊（例如以 `:` 结尾的自定义提示符），会退化为"输出静默 2 秒"
    或"超时"，此时可在批量下发对话框切回固定间隔模式。
16. **巡检并发不要开太大**：并发数过高可能触发设备侧登录限制（VTY 线路数）、
    管理网拥塞。默认 4，一般 5~10 台以内比较稳妥；`[Y/N]` 类命令会让该设备提前停止。
17. **Excel 单元格上限 32000 字符**：超长命令输出会被截断并标注"内容过长已截断"；
    需要完整输出请用会话日志（`~/.aiterminal/logs/`）。
18. **笔记手册只合并文本笔记**：`.md` / `.txt` 参与合并，PDF / Word / Excel 等原始文档
    不会塞进手册（但仍在资料库里可被检索）。

## 7. 与原始设计稿的差异（Bug 修正与补全）

原始文档只给出了部分文件代码，本次实现补全了缺失模块，并修正了以下问题：

| # | 位置 | 问题 | 处理 |
| --- | --- | --- | --- |
| 1 | `telnet_connector.py` | Python 3.13 已移除 `telnetlib`，直接 `import` 会崩 | 探测导入 + 内置 `_MiniTelnet` 回退 |
| 2 | `main_window.py` | `output_received` 信号与 100ms 轮询同时向终端追加，输出重复一倍 | 只保留轮询作为唯一显示路径，信号用于 AI 上下文 |
| 3 | `terminal_widget.py` | 按键处理末尾调用基类 `keyPressEvent`，Backspace/方向键会删改已显示的设备输出 | 拦截并 `return`，不落到默认文本编辑行为 |
| 4 | `main_window.py` | `session_created` 信号未连接，创建会话后不会生成标签页 | 由 `on_session_created` 统一建标签页并接线 |
| 5 | `ssh/telnet/serial_connector` | `disconnect()` 无条件发 `connection_lost`，重复触发 | 仅在实际处于连接态时发射 |
| 6 | `ai_panel.py` | "分析当前输出/执行AI命令"按钮的回调是空实现 | 改为定义信号，由主窗口接管 |
| 7 | `session.py` | AI 自动执行循环缺失 | 新增 `ai_step()` 与主窗口 `ai_tick()` 心跳 |
| 8 | 全局 | 危险命令只写在提示词里，无代码级兜底 | `AIAgent.is_dangerous()` 黑名单 + `filter_commands()` 拦截 |
| 9 | 缺失文件 | `core/terminal.py`、`config/*`、`plugins/base.py`、`resources/styles/dark.qss` 等 | 全部补齐 |

## 9. 常见问题

**Q: 连接设备后终端没有回显？**
部分设备关闭了 echo。此时可在设备上执行 `terminal monitor` / `screen-length 0 temporary`，
或依赖界面底部输入回显条确认输入内容。

**Q: 华为/H3C 设备输出分屏卡住？**
登录后先执行 `screen-length 0 temporary`（H3C/华为）或 `terminal length 0`（Cisco）关闭分屏。

**Q: AI 生成的命令被拦截了？**
`reboot`、`delete`、`erase`、`undo all` 等命中危险黑名单，AI 面板会提示"安全拦截"，
需要人工在终端里手动执行。

**Q: 串口列表为空？**
确认驱动已安装（CH340/CP210x/FTDI），点"刷新"重新枚举。

**Q: 会话日志存在哪里？**
`~/.aiterminal/logs/日期/` 下，一个会话一个文件（文件名含会话名、主机、时间戳）。
工具菜单的"打开日志目录"可以直接打开。日志默认开启，可在同一菜单关闭。

**Q: 批量下发的命令没生效？**
默认每条间隔 500ms，慢设备请在模板对话框里把间隔调大。
另外进入配置视图（`system-view` / `configure terminal`）后的命令需要按视图层级排列，
可在命令预览区里手工调整顺序后再下发。

**Q: 配置快照采不到内容？**
快照是"下发命令 → 等输出稳定 → 存档"，如果设备开了分屏（`---- More ----`）会卡住，
请先执行 `screen-length 0 temporary`（华为/H3C）或 `terminal length 0`（Cisco）。

**Q: 联网查询报"没有返回结果"？**
依次检查：AI 面板"联网查询"页签的后端是否被设成了"关闭"；
网络能否访问百度/必应；若都不行，可自建 SearXNG 并在设置里填实例地址。
`last_error` 会记录具体失败原因，界面上会显示。

**Q: AI 生成的命令我没有让它执行，它自己跑了吗？**
不会。默认是"待执行队列 + 自动模式关闭"：AI 只生成命令，进入"待执行"页签等你勾选。
只有手动打开"自动模式"后才会自动下发，且危险命令（reboot/delete/erase 等）始终被拦截。

**Q: Console 连上但设备没反应？**
先确认波特率（9600 或 115200）、帧格式 8-N-1、行结束符为 CR；
再用工具栏"串口控制"发一次 Break 或把 DTR 拉低试试。
设备不回显时请在连接对话框勾选"本地回显"。

**Q: 串口突然断了？**
如果勾了"自动重连"，插回 USB 转串口线后会按间隔自动恢复，状态栏会提示重连进度；
也可以点"串口控制 → 重新连接"手动触发。

**Q: 我把手册导进去了，但 AI 还是说查不到？**
按这个顺序查：

1. 资料库管理窗口里看该文件的**状态**是不是"已索引"。是"待索引"就点"重建索引"；
   是"无法解析"就看提示原因（扫描件 PDF 需先 OCR，老版 .doc 需转格式）。
2. 在同一个窗口用**检索测试**输入关键词。测试查不到，说明关键词和手册措辞差太远，
   换个更具体的词（带上型号或完整命令）。
3. 确认"查命令时检索本地资料库"是勾上的。
4. AI 检索关键词是模型自己拟的；你也可以直接在"资料检索"页签手动提问，
   手动提问同样会先查本地资料库。

**Q: 导入会动我原来的下载文件吗？**
默认是**复制**，原文件不动。只有显式勾选"导入后删除源文件（移动）"才会移走。
删除资料库里的文件也只会删副本，并且被限制在资料库目录内。

**Q: 索引文件 `.index.json` 可以删吗？**
可以，删掉后下次会自动重建，只是首次重建会慢一点（取决于文档数量与 PDF 大小）。

**Q: 我沉淀的笔记存在哪？怎么改？**
存在 `~/.aiterminal/knowledge/<分类>/` 下的 Markdown 文件里，可以用任何编辑器直接改；
改完在资料库窗口点「重建索引」让改动生效（改文件会让索引自动判定为需要重建，
其实不点也行，下次检索前会自己更新）。

**Q: 同一个命令存了两次会不会重复？**
文件层面不会覆盖（同名自动加 `_2` 序号），检索时也会按相似片段去重。
如果确实想清理，在资料库窗口里删除多余的那份即可。

**Q: 沉淀的笔记会不会泄露到网上？**
不会。本地资料库的检索完全在本地完成，不会上传；只有当你点了"查资料"、
需要模型组织答案时，命中的片段才会随请求发给模型 API。

**Q: 批量下发卡在某一条不动了？**
大概率是该命令触发了分页或确认提示。勾上"自动翻页"可以处理 `---- More ----`；
如果是 `[Y/N]` 确认提示，程序会主动停下并提示你手动应答（这是有意设计的，
避免自动按下 Y 造成误操作）。也可以把等待方式切成"固定间隔"应急。

**Q: 巡检时某台设备显示"需人工确认"？**
该设备执行到了需要确认的命令（如 `save`），程序已停止它的后续命令。
其余设备不受影响。可以手动连上去应答后单独再跑一次。

**Q: 巡检导出 Excel 打不开？**
文件是标准 OOXML 格式，Excel / WPS / LibreOffice 都能打开。
如果提示损坏，请确认导出过程中磁盘没有被占用，或改用「导出 CSV」。

**Q: 导出的手册怎么变成 PDF？**
选 HTML 格式导出，用浏览器打开后 `Ctrl+P` 打印为 PDF，样式已经为打印优化过。
