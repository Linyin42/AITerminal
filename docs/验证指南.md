# AITerminal 功能验证指南

按顺序走完这 5 步，就能确认从"连上设备"到"AI 辅助 + 批量运维"整条链路是否正常。
**第 1 步建议一定要做**：命令行验证比图形界面更容易定位问题，5 分钟就能确认设备侧没问题。

---

## 第 0 步：离线自检（不需要任何设备，1 分钟）

先确认程序本身没问题。

```bash
# 1) 语法与逻辑自检：341 项断言，不需要设备、不需要联网
python tests/smoke_test.py
# 期望输出最后一行：全部通过 ✔
```

再确认"连接→命令→分页→提示符判定"这条链路本身是通的（用内置模拟设备）：

```bash
# 终端 A：启动模拟设备（模拟一台 H3C 交换机，开了分页）
python tools/fake_device.py --port 2323 --no-login --paging

# 终端 B：验证工具连上去跑一遍
python tools/verify_device.py --protocol telnet --host 127.0.0.1 --port 2323
```

期望看到：连接成功、识别为 H3C、3 条命令全部"完成（提示符返回）"、耗时都在 1 秒内。

## 第 1 步：命令行验证真实设备（推荐先做）

### 准备

```bash
pip install -r requirements.txt
```

### 命令（三种连接方式）

```bash
# SSH（最常用）
python tools/verify_device.py --protocol ssh --host 10.0.0.1 --user admin
#   ↑ 回车后会提示输入密码，输入时不回显、也不会留在命令历史里

# Telnet
python tools/verify_device.py --protocol telnet --host 10.0.0.1 --user admin

# Console 串口（先看有哪些串口）
python tools/verify_device.py --list-ports
python tools/verify_device.py --protocol serial --serial-port COM3 --baudrate 9600
```

### 它会依次告诉你

| 步骤 | 检查内容 |
| --- | --- |
| 1 | 连接是否成功、耗时多少 |
| 2 | 设备是否回显、**厂商识别**（华为/H3C/Cisco/锐捷） |
| 3 | 关闭分屏命令是否生效（`screen-length 0 temporary` / `terminal length 0`） |
| 4 | 每条命令能否"等提示符返回"地执行完，并打印输出 |

### 常用参数

```bash
--commands "display version,display interface brief,display current-configuration"
    # 自定义要跑的命令（默认 3 条基础巡检命令）

--show-lines 40          # 每条命令多显示几行输出，便于判断内容对不对
--prompt-timeout 60      # 大配置输出慢，加长等待
--delay-mode --delay 2   # 不用等提示符，改用固定间隔（提示符不标准时兜底）
--no-prepare             # 不自动关分屏（想验证分页自动翻页时用）
--allow-dangerous        # 允许下发 reboot/delete 等（默认被安全拦截）
```

### 结果判读

- **`√ 链路验证通过`** → 设备侧完全没问题，直接进第 2 步。
- **`× 连接失败`** → 按它给出的排查建议走，通常是：地址端口不通 / 认证失败 /
  设备没开 telnet server / 串口被 MobaXterm 等占用。
- **`超时未完成`** → 加 `--delay-mode` 再试；还是不行就加 `--prompt-timeout 60 --show-lines 40`
  把输出发出来看。
- **`需人工确认`** → 该命令（如 `save`）要交互确认，这是有意的安全设计，不会替你按 Y。

### 关于密码的安全提醒

- **推荐**：不带 `--password`，让工具交互式询问（不回显、不进历史）。
- 也可以用环境变量：`set AITERM_PASSWORD=xxx`（Windows）然后 `--password-env AITERM_PASSWORD`。
- **不建议**：`--password 明文` 会留在 shell 历史里。
- **不要**把密码贴在聊天/工单/截图里；如果已经贴过，测试完请改掉设备密码。

## 第 2 步：图形界面验证连接与终端（3 分钟）

```bash
python main.py
# 或 Windows 双击 run.bat（首次会自动建虚拟环境装依赖）
```

1. 工具栏 **「新建连接」** → 选协议 → 填地址/账号密码 → **连接**
2. 在终端里敲 `display version`，确认：
   - 设备输出正常显示（ANSI 颜色被清洗，不会出现乱码转义符）
   - 底部输入回显条能实时看到自己输入的内容
   - ↑↓ 能翻命令历史，Ctrl+C 能中断
3. **Console 会话额外验证**：工具栏 **「串口控制」**
   - 发送 Break（进 BootROM 用）
   - DTR / RTS 电平切换
   - 运行时切换波特率
   - 「重新连接」按钮
   - 设备不回显时，在连接对话框勾选 **本地回显**

## 第 3 步：验证 AI 辅助（需要 Anthropic API Key，5 分钟）

1. 右侧 AI 面板 → **AI 助手** 页签 → 填入 API Key（会自动保存）
2. 在设备上敲一条命令（例如 `display version`），让屏幕上有内容
3. 在「任务描述」里写一句，例如 `检查设备版本和接口状态`
4. 点工具栏 **`AI: OFF`** 切成 **ON** → 进入建议模式
   - 期望：AI 输出 `[AI] xxx` 形式的命令，进入 **待执行** 页签
   - 点「执行勾选项」才会真正下发（默认不自动执行）
5. 验证 **自动模式**：勾选「自动模式（AI自动执行命令）」
   - 期望：输出稳定后 AI 自动分析并下发命令；任务完成或需要人工确认时自动暂停
   - 危险命令（`reboot`/`delete`/`erase`/`undo all`）始终被拦截
6. 验证 **AI 联网查资料**：AI 面板 → **资料检索** 页签
   - 输入 `H3C S5560 怎么配置端口镜像` → 点「查资料」
   - 期望：给出结论 + 命令，下方列出参考来源（【本地】/【网页】），双击可打开

> 「屏幕内容（AI 可见）」预览区显示的就是 AI 实际能看到的内容，
> 如果 AI 答非所问，先看这里是不是内容不对。

---

## 第 4 步：验证本地资料库与知识沉淀（不需要设备，3 分钟）

1. 工具栏 **「导入资料」** → 选一份你下载好的命令手册（PDF/Word/txt 都行）
   - 期望：提示已导入，并自动建索引
2. 工具栏 **「资料库」** → **文档与笔记** 页签
   - 看状态列是不是「已索引(N段)」；不是就点「重建索引」
   - 切到 **检索测试** 页签，输入 `端口镜像` 或 `display cpu-usage`
   - 期望：显示命中的片段和来源文件 —— 这一步说明 AI 之后也能查到
3. 回到 AI 面板「资料检索」页签再问一次同样的问题
   - 期望：参考来源里出现 **【本地】** 标记
4. 点 **「💾 存为资料」** 把答案沉淀下来
   - 期望：落到 `~/.aiterminal/knowledge/命令速查/` 下，再问同一主题能直接命中自己的笔记
5. 在资料库窗口用 分类/标签/关键词 筛选，点 **「📘 导出为手册…」**
   - 期望：导出一份 Markdown 或 HTML 手册（HTML 可直接打印成 PDF）

## 第 5 步：验证批量下发与并发巡检（有 2 台以上设备时做）

### 批量下发（单台）

1. 打开一个会话 → 工具栏 **「批量下发」**
2. 选一个模板（如「设备基础巡检」）→ 检查命令预览 → 点「下发到当前会话」
3. 期望：等待方式默认「等提示符返回」，每条命令完成后才发下一条；
   遇到 `---- More ----` 自动翻页；遇到 `[Y/N]` 会停下并提示你手动应答
4. 跑完用 工具菜单 → **「导出上次批量下发结果」** 存成 Excel

### 并发巡检（多台）

1. 工具栏 **「多设备巡检」**
   - 已打开的会话会自动加入列表；也可以「添加最近连接」
2. 填命令或从模板载入 → 设并发数（建议 4，别开太大）
3. 点「开始巡检」→ 看进度条与日志
4. 完成后点 **「导出 Excel」**
   - 期望：三个工作表 **巡检信息 / 巡检汇总 / 命令明细**
   - 巡检用独立连接，不会影响界面上已打开的会话

## 验证过程中已修复的两个问题（记录）

用上面的流程实测时发现并修掉了两个真实缺陷，你拿到的版本已经包含修复：

1. **Telnet 输出按 10 秒一批才交付**：`_MiniTelnet.read_very_eager()` 会阻塞到
   socket 超时才返回，导致会话看起来卡顿（每条命令都等 10 秒）。
   改为临时把 socket 设为非阻塞后，响应从 **10.1 秒降到 0.1 秒**。
2. **Telnet 登录慢且易失败**：原来写死匹配 `login:` / `Password:` 并各等 5 秒，
   遇到 `Username:` 之类的提示语就白等超时（实测连接要 11 秒）。
   改为兼容多种提示语（`login:` / `Username:` / `login as:` / `Password:` / `Passwd:` 等）、
   匹配到立刻输入、并先唤醒设备（部分 Telnet 转 Console 需要先敲回车），
   连接耗时从 **11 秒降到 0.5 秒**，且登录阶段的数据不再丢失。
